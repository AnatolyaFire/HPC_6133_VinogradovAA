## Описание

Реализованы два варианта алгоритма умножения квадратных матриц:

| Версия | Подход | Особенности |
|--------|--------|-------------|
| CPU | Последовательный | Порядок обхода i-k-j для кэш-локальности |
| GPU | CUDA, параллельный | Блоки 16×16, разделяемая память (shared memory) |

---

## Алгоритмы

### CPU — порядок обхода i-k-j

Классический алгоритм с оптимизацией кэша: внешний цикл по `i`, средний по `k`, внутренний по `j`. Элементы матрицы **A** переиспользуются во внутреннем цикле, что минимизирует промахи кэша.

### GPU — разделяемая память (Shared Memory)

- Каждый поток вычисляет **один элемент** результирующей матрицы
- Потоки объединяются в блоки **16×16 = 256 потоков**
- Каждый блок загружает тайлы A и B в shared memory
- Количество обращений к глобальной памяти сокращается в **16 раз**

```
Grid → Blocks (16×16) → Threads
         ↓
    Shared Memory (tile A + tile B)
         ↓
    __syncthreads() → накопление суммы
```

## Требования

- **CUDA Toolkit** 11.8 или выше
- **NVIDIA GPU** с Compute Capability ≥ 5.0
- Компилятор `nvcc` с поддержкой C++11

> Тестирование проводилось на **Tesla T4** (Compute Capability 7.5, 40 SM, 14912 MB)

---

## Запуск

```bash
# Компиляция
nvcc -arch=sm_75 -o matrix_mult matrix_mult.cu

# Запуск
./matrix_mult
```

> Для других GPU замените `sm_75` на архитектуру вашей карты:
> RTX 30xx → `sm_86`, RTX 20xx → `sm_75`, GTX 10xx → `sm_61`

| 250 × 250 | 0.0987 | 0.0009 | **112.4x** |

| 1250 × 1250 | 13.0333 | 0.0545 | **239.3x** |

**Среднее ускорение: 173.04x**

## Анализ

### Зависимость ускорения от размера

| Диапазон | Ускорение | Причина |
|----------|-----------|---------|
| Малые (100–250) | 20x → 112x | Накладные расходы на передачу данных и запуск ядра значительны |
| Средние (500–1000) | 154x → 243x | Вычислительная нагрузка растёт быстрее накладных расходов |
| Большие (1250–1500) | 239x → 253x | Ускорение стабилизируется у теоретического предела GPU |

### Ключевые факторы производительности

- **Shared memory** — сокращает обращения к глобальной памяти в 16 раз (размер тайла = 16)
- **Размер блока 16×16** — оптимальный баланс между загрузкой shared memory и числом потоков
- **Тип `double`** — высокая точность, но меньшая пропускная способность по сравнению с `float`
- **Накладные расходы** — передача данных через PCIe и запуск ядра заметны только для малых матриц
