
### 2. Реализация на CPU

В CPU-реализации использован классический алгоритм с оптимизацией порядка обхода циклов **i-k-j**. Такой порядок выбран для улучшения локальности данных в кэш-памяти процессора:

- Внешний цикл по i (строки результирующей матрицы)
- Средний цикл по k (общий индекс для A и B)
- Внутренний цикл по j (столбцы результирующей матрицы)

При таком порядке элементы матрицы A переиспользуются во внутреннем цикле, что минимизирует промахи кэша и повышает производительность.

### 3. Реализация на GPU (CUDA)

GPU-реализация использует следующие принципы параллелизации:

#### 3.1. Декомпозиция задачи

- Каждый поток вычисляет один элемент результирующей матрицы
- Потоки объединяются в блоки размером 16×16
- Блоки образуют сетку (grid), покрывающую всю матрицу

#### 3.2. Использование разделяемой памяти (shared memory)

Ключевая оптимизация заключается в использовании быстрой разделяемой памяти:
- Каждый блок загружает в shared memory подматрицы A и B размером 16×16
- Данные многократно переиспользуются в пределах блока
- Количество обращений к глобальной памяти сокращается с O(N³) до O(N³/16)

#### 3.3. Что было распараллелено

- **Вычисления элементов матрицы**: N² потоков работают одновременно
- **Загрузка данных в shared memory**: потоки блока загружают данные параллельно
- **Накопление сумм**: каждый поток независимо вычисляет сумму произведений

### 2. Анализ времени выполнения

- **CPU-реализация** демонстрирует ожидаемую кубическую зависимость времени от размера матрицы. Для N=1500 время выполнения составляет 22.49 секунды.

### 3. Точность вычислений

Верификация результатов показала максимальную разницу между CPU и GPU вычислениями **0.0000**, что подтверждает корректность реализации. Отсутствие различий объясняется использованием одинакового типа данных double и правильной организацией вычислений.

### 4. Факторы, влияющие на производительность

| Фактор | Влияние |
|--------|---------|
| Размер матрицы | Чем больше размер, тем выше эффективность GPU за счет преобладания вычислительной работы над накладными расходами |
| Размер блока (16×16) | Выбран оптимально для баланса между загрузкой shared memory и количеством потоков |
| Использование shared memory | Сокращает обращения к глобальной памяти в 16 раз, что значительно ускоряет вычисления |
| Тип данных (double) | Обеспечивает высокую точность, но снижает пропускную способность по сравнению с float |
